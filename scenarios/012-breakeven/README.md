# 012-breakeven — 圧縮辞書は何回目の更新で元が取れるか

## 何を測るか

[`012-dictionary`](../012-dictionary/README.md) が示すのは「**2 回目以降の訪問者**にとって差分がどれだけ小さいか」だけです。導入すべきかを決めるには、**払う側**も見なければ片側の勘定になります。

🔴 ただし「初回コスト vs 再訪利得」という枠組みは、**どちらの流し方を採るかで意味が変わります**。

| 流し方 | 辞書の実体 | 初回の追加コスト |
|---|---|---|
| **すでに配ってある資源を辞書にする**（`012-dictionary` で測った形）| 前のデプロイの `bundle-v1.js` | **ゼロ**。訪問者はアプリとしてどのみち受け取っている |
| **専用の辞書ファイルを配る**（`<link rel="compression-dictionary">`）| 別途配る辞書 | **辞書のバイト数ぶん増える** |

前者には**分岐点そのものが存在しません**。2 つを混ぜて 1 つの分岐点を出すと、存在しないコストを勘定に入れた数字になります。

## 記事のどこに出るか

決定表 1 の「導入すべきか」。

## 判定

辞書代（**ワイヤ上**＝圧縮した状態のバイト数）÷ 更新 1 回あたりの節約（`br` − `dcb`）で、元が取れる更新回数を出します。素の大きさで勘定しません。

変更率は [`012-crossover`](../012-crossover/README.md) の結果を使います。**更新のたびにどれだけ変わるか**で節約額が変わるためです。

## 実行

```bash
bash scenarios/012-crossover/run.sh   # 先にこちら
bash scenarios/012-breakeven/run.sh
```

## 未測定

実トラフィックでのキャッシュヒット率・訪問頻度は仮定していません。ここで出しているのは**バイト数の勘定**だけです。
