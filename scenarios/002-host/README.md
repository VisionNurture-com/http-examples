# 002-host — 削ると壊れる、ただ 1 本

## 何を測るか

RFC 9112 §3.2 は HTTP/1.1 のリクエストに `Host` を必須と定めています。**それが実装でどう出るか**を、3 つの経路で測ります。

| 経路 | 入口 |
|---|---|
| nginx 単独（静的） | `/002/static/sample.html` |
| nginx→Express | `/002/api/echo`（8087） |
| Express 直結 | `/002/api/echo`（8086・nginx を通さない） |

## なぜ 3 経路か

「壊れた」ときに**どの層が拒んだか**を分けるためです。nginx だけが弾いているのか、その先の Express も弾くのかは、片方だけ測っても分かりません。

## 判定

`-H "Host:"` で curl に送信を止めさせ、返ってきた応答コードを見ます。curl 自身が送信を拒んだ場合（終了コードが 0 以外）も区別して記録します。**curl が弾いたのをサーバの判定と読み違えないため**です。

## 記事のどこに出るか

決定表の「削ると壊れる」側。12 本のうちここに入るのは 1 本だけ、という結論の裏づけ。
