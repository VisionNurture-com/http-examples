# 012-vary — Vary を落とすと共有キャッシュが何を配るか

## 何を測るか

辞書つきの応答は、**辞書を持つ客にしか読めません**。`Vary` を落とすと、共有キャッシュは「辞書の有無で応答が変わる」ことを知りようがなく、**辞書を持つ客への差分を全員へ配ります**。

🔴 **説明ではなく再現にします。** 前段に `proxy_cache` を実際に置き、**辞書を持つ客 → 持たない客**の順に同じ URL を叩きます。設定を外して眺めるだけでは、事故を説明しただけで再現していません。

## 埋める欄

決定表 1 の運用注意。設定の警告を**実物**で見せる材料。

## 判定

🔴 **判定は「復号できたか」ではなく「受け取ったバイト列が元のファイルと一致するか」で取ります。** 復号可否はクライアント実装の親切さに左右されますが、バイト列の一致は左右されません。

対照として、同じ内容で `Vary` を出す入口（`/012/withvary.js`）も同時に測ります。片側だけでは「キャッシュが効いていなかっただけ」と区別できません。

## 実行

```bash
docker compose up -d --wait
node tools/make-012-artifacts.mjs
bash scenarios/012-vary/run.sh
```

🔴 試行ごとにキャッシュキーを変えます（`VARY_RUN_ID`）。前の試行の状態を持ち込むと、2 人目が MISS になるか HIT になるかが変わってしまいます。
