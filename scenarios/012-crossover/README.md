# 012-crossover — 辞書はどこまで効くか

## 何を測るか

[`012-dictionary`](../012-dictionary/README.md) は「同じアプリの次のデプロイ」で **dcb が br の 45 分の 1** になることを示します。ただしこれは**差分が小さいとき**の数字です。この 1 点だけを見た読者は、自分の条件に当てはめられません。

そこで**変更率を振り**、辞書ありの差分（`dcb` / `dcz`）が辞書なしの圧縮（`br` / `zstd`）に追い抜かれる点まで測ります。

## 変更のモデルと、その限界

v1 を行単位で見て、先頭から一定割合の行を辞書に無い内容へ置き換えます。**実際のデプロイの差分そのものではありません**。「どれだけ違うか」の目盛りとして使います。

🔴 置換行は**元の行と同じくらいの長さ**にしています。長い行で置き換えると、変更率を上げるほどファイル自体が太り、「差分が大きいから負けた」のか「ファイルが大きいから負けた」のか分けられなくなるためです。実際、素朴に置き換えた最初の版では 100% 変更時に identity が 99,353 → 190,914 バイトへ膨らんでいました。

## 記事のどこに出るか

決定表の「コンテンツ種別 × 更新頻度 → 圧縮方式」。更新のたびにどれだけ変わるかで選び分けるための目盛り。

## 判定

辞書ありのバイト数が辞書なしを上回った最初の変更率を追い抜かれる点とします。差分側には RFC 9842 の固定ヘッダぶん（`dcb` = 36 バイト / `dcz` = 40 バイト）を足して比べます。

## 実行

```bash
bash scenarios/012-crossover/run.sh
```

サーバもブラウザも要りません。
