# 005-failure-replay — 失敗した結果を保存するかで、送り直しの結果が変わる

## 何を測るか

課金は済んだのに、その直後に失敗して 500 を返した、という場面を作る。
呼び出し側から見えるのは「どこまで進んだか分からない失敗」だけなので、同じキーで送り直す。

| 実装 | 失敗した結果 | エンドポイント |
|---|---|---|
| B | 保存しない（v07 準拠の実装）| `POST /005/charge` |
| B-save | 保存して、同じキーの送り直しには保存した 500 を返す | `POST /005/charge-save-failures` |

B-save は、Stripe の公開ドキュメントが書く方針（成功でも失敗でも最初の結果を保存し、500 も同じ結果を返す）に合わせた。

## 記事のどこに出るか

sec06「自分の API に入れる」の「何を保存するか」。

## 実行モード

**M1**（ブラウザ不要）。CI で回る。

## 測り方

- 1 本目には測定用の口 `?fail_after_charge=1` を付け、課金のあとで失敗させる。2 本目は同じキー・同じ本文で口を付けずに送る
- 指紋はパスと本文から作るので、クエリの有無では変わらない
- 各実装を 20 回くり返し、2 本目の応答とサーバが数えた課金回数を記録する

🔴 測定用の口は、失敗の場面を作るためだけのもの。本番のコードに置かない。
