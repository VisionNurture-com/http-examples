# 005-multiprocess-idempotency — 排他はプロセスの外へ出ると効かない

## 何を測るか

冪等キーの実装は「生成・保存・排他」の 3 か所でできている。このうち**排他だけがプロセスに閉じている**。

記事 005 の実装は `const inFlight = new Set()` で処理中のキーを覚えており、同じ台に 2 本目が来れば 409 で弾ける。
ところがサーバを 2 台に並べると、2 台目はそのキーが処理中であることを知らない。

記事は本文 1 行で「複数台に分けた場合は測っていません」と断っていた。ここを測る。

## 記事のどこに出るか

sec06「自分の API に入れる」の排他の節。限定の 1 行を、実測に置き換える。

## 実行モード

**M1**（ブラウザ不要）。CI で回る。

## 測り方

- **ロードバランサは挟まない。**振り分けの運不運が入ると、弾けた理由が排他なのか偶然なのかを分けられない
- 2 本をそれぞれ別のインスタンスへ直接送る。機序をそのまま観測するため
- **課金回数は両方のインスタンスから読んで足す。**`charged` もプロセス内の変数のため、片方だけでは見落とす
- 対照として「同じインスタンスへ 2 本」も毎回測る。B がそちらでは 1 回に抑えることを示すため
