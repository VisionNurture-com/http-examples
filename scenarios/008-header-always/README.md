# 008-header-always — `add_header` が応答から落ちる条件

## 何を測るか

CORS の設定を書いたのに効かない原因のうち、**ブラウザではなくサーバ側にあるもの**を切り出します。nginx 公式ドキュメントが定める 2 つの規則を、実際の応答で確かめます。

1. `add_header` は既定で 200 / 201 / 204 / 206 / 301 / 302 / 303 / 304 / 307 / 308 にしか付かない。`always` を付けると応答コードに関係なく付く
2. 現在のレベルに `add_header` が 1 つでもあると、親レベルの `add_header` は継承されない。**1.29.3 で追加された `add_header_inherit merge;`** で足せる

## 記事のどこに出るか

実効値の表「サーバ側で CORS ヘッダが落ちる条件」の**実効値**欄。

## 判定

`curl` の応答ヘッダ。**ブラウザは使いません。**これはサーバ側の性質であり、ブラウザの表示に依存しないためです。記事にも「ブラウザで観測した」とは書きません。

`results/008-header-always/run.log` に応答ヘッダをそのまま残し、`tools/aggregate-008-header-always.mjs` が CORS ヘッダの本数を機械的に数えます。
