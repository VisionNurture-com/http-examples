# 002-minimize — 削って測ると、何本残るか

## 何を測るか

「DevTools からコピーしたのに動かない」という出発点に対して、**コピー元のヘッダを 1 本ずつ落とし、結果が変わる点を探します**。ヘッダの意味を並べるのではなく、手続きを回した結果を出します。

## 手順

1. 受け取ったヘッダをそのまま返す口（`/002/api/echo`）へ、実ブラウザで素のナビゲーションを 1 回投げて**送られた集合を採る**
2. その集合を curl で再現し、**1 本ずつ落として** 4 点を比べる
3. 「変わらない」と判定した全ヘッダを**まとめて落として**、基準と一致するか検算する

## 判定（4 点比較）

| 点 | 見るもの |
|---|---|
| ① | status |
| ② | レスポンスヘッダの集合（`Date` は除く） |
| ③ | body の SHA-256 |
| ④ | body のバイト数 |

status だけを見ると、**200 のまま中身が変わる**型（圧縮の有無・本文が空で届く）を取りこぼします。

分類は 3 つです。**A 壊れる**（status が変わった）/ **B 壊れないが変わる**（status は同じで ②〜④ のどれかが動いた）/ **C 変わらない**。

## 4 通し

「nginx が弾いたのか Express が弾いたのか」を分けるため、経路と本文の種類を組み合わせて 4 通り回します。

| 通し | 入口 |
|---|---|
| 静的 GET × nginx 単独 | `/002/static/sample.html` |
| 静的 GET × nginx→Express | `/002/api/static` |
| JSON POST × nginx 単独 | `/002/static/sample.html`（静的配信への POST） |
| JSON POST × nginx→Express | `/002/api/echo` |

## echo を相手にするときの注意

echo は受け取ったヘッダをそのまま返すため、1 本削れば応答の長さが必ず動きます。そのままでは全ケースが「変わった」に倒れて分類が成立しません。そこで echo の通しだけは `content-length` / `etag` を比較から外し、代わりに**サーバが要求をどう扱ったか**（メソッド / 届いたバイト数 / そのハッシュ）を取り出して比べています。

## 記事のどこに出るか

決定表「削ってよい / 削ると壊れる / 壊れないが結果が変わる」の 3 分類そのもの。

## 実行

```bash
node tools/capture-002-browser.mjs      # 実ブラウザ 3 エンジンの採取（先に 1 回）
bash scenarios/002-minimize/run.sh
```

採取には実ブラウザが要るため CI では回りません。採取結果を置いたあとは `run.sh` だけで再現できます。
