# 006-hard-reload — 通常リロードとハードリロードで扱いが変わるか

## 何を測るか

「`immutable` が確実に効くのはフォースリロード（Cmd+Shift+R）のときだけ」という説明を目にします。これが今も成り立つのかを、通常リロードと並べて測ります。

| 経路 | 送るキー |
|---|---|
| 通常リロード | Cmd+R |
| ハードリロード | Cmd+Shift+R |

## なぜ GUI 操作なのか

ハードリロードに対応する自動化 API がありません。Playwright の `page.reload()` は通常リロード相当で、`page.keyboard.press()` で送ったキーは headless ではブラウザ本体に届きません（実測で確認）。そのため headed で起動し、OS 経由でキーを送っています。

macOS のアクセシビリティ許可（`/usr/bin/osascript`）が要ります。

## 記事のどこに出るか

実効値の表「immutable は今も効くのか」の経路欄。

## 判定

サーバ側の到着記録（`results/006-cache/access.log`）。

🔴 **キーが届かなかったことを「再取得しなかった」と読まないための事前条件を置いています。** 判定ページは `no-store` なので、リロードが起きていればページ自身が必ず再要求されます。ページの再要求が 0 件なら、それはブラウザが何も受け取っていないという意味なので、測定不成立として落とします。

## 読者が手元で確かめる手順

1. サーバのアクセスログを見られる状態にする
2. ページを開き、**Cmd+R** を押す → アセットの行が増えないことを確認
3. 続けて **Cmd+Shift+R** を押す → アセットの行が `200` で増えることを確認

`immutable` の有無で 2 と 3 の結果が変わらなければ、この指定はその経路に効いていません。
