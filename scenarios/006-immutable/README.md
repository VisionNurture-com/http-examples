# 006-immutable — immutable は今も効くのか

## 何を測るか

`Cache-Control: immutable` は「fresh のあいだ応答は更新されないので、条件付きリクエストを出さなくてよい」とキャッシュに伝える指定です（[MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cache-Control)）。もともとは、リロードのたびにブラウザが期限内のサブリソースまで再検証してしまう挙動を止めるために入りました。

そこで `max-age=600` だけの応答と `max-age=600, immutable` の応答を並べ、**通常ナビゲーションとリロードで別々に**測ります。2 つを分けるのは、リロードのときだけ再検証が起きるという前提を確かめるためです。

Firefox は immutable を https のときだけ honor すると報告されているため、**http と https の両方**で測ります。

## 記事のどこに出るか

実効値の表「immutable は今も効くのか」の実効値欄。

## 判定

サーバ側の到着記録（`results/006-cache/access.log`）。2 回目の読み込みで、そのアセットの行が増えたかどうかで判定します。

| 到着 | 意味 |
|---|---|
| 0 件 | キャッシュから読んだ（訊きにも来ていない） |
| status=304 | 訊きに来たが本体は送っていない |
| status=200 | 取り直した |

判定は生ログのカウントのみで機械的に行い、**予測と食い違ってもそのまま記録します**。

## 対照（測定の事前条件）

測定の前に 3 つの対照を取り、1 つでも崩れたら値を書き出さずに中止します。

| 対照 | 変種 | 崩れたときに疑うこと |
|---|---|---|
| 陰性 | `max-age=600` の 2 回目が 0 件 | そもそもキャッシュが働いていない |
| 陽性 | `no-store` の 2 回目が必ず到着 | 観測チャネル（nginx のログ）が死んでいる |
| 条件付き | `no-cache` の 2 回目が 304 | 「訊きに来たこと」を観測できていない |

3 つ目がないと、「到着 0 件」を「条件付きリクエストすら出さなかった」と読むことができません。沈黙と測定値の区別がつかないためです。
