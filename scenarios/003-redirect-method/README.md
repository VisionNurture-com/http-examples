# 003-redirect-method

リダイレクトを追いかけたとき、メソッドとボディがどうなるかを測ります。クライアントは curl です。

## 何を測るか

5 つのステータス（301 / 302 / 303 / 307 / 308）× 3 通りの書き方で POST を送り、**転送先に届いたメソッドと本文の長さ**を記録します。

| 書き方 | 指定 |
|---|---|
| `implicit` | `-d` だけ。メソッドは curl が決める |
| `forced` | `-X POST` を足す |
| `post30x` | `--post301 --post302 --post303` で変換をやめさせる |

サーバ側が決めるのは返すステータスだけです。メソッドをどう扱うかはクライアントの判断なので、書き方ごとに測る必要があります。

## 実行

```bash
docker compose up -d --wait
bash scenarios/003-redirect-method/run.sh
```

## 測り方の注意

- 判定は転送先の到着記録（メソッドと本文の長さ）で行い、クライアントの申告では読みません
- nginx は既定で絶対 URI の `Location` を組み立てます。コンテナ内の listen ポートが入ってホスト側から追えなくなるため、`absolute_redirect off;` で相対参照にしています。測る対象はメソッドの変換であってポート転送ではないためです
- 対になるブラウザ側の測定は `003-redirect-browser`（M2）にあります
