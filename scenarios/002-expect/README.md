# 002-expect — 自分では書いていないヘッダ

## 何を測るか

`Expect: 100-continue` は、**書いていないのに送られる**ヘッダです。curl は本文がある大きさを超えると自動で付けます。手元では動くのに本番で落ちる、あるいはその逆が起きる原因になります。

測るのは 2 つです。

1. curl が**自動で付け始める大きさ**
2. その本文を、**上限設定の違う 2 つの口**へ送ったときの返り方

## なぜ 2 つの口か

nginx の既定 `client_max_body_size` は 1m で、curl が `Expect` を付け始める大きさとほぼ重なります。既定のままだと **100 Continue の代わりに 413 が返る**ため、「100 Continue が返る側」を観測できません。上限だけを変えた口（`/002/large/`）を並べ、同じ本文で応答が分かれることを見ます。

## 判定

`curl -v` のトレースから、送信側の `> Expect: 100-continue` と、応答側の `< HTTP/1.1 100` を読みます。どちらも `-v` にしか出ません。

## 記事のどこに出るか

決定表の「自分が書いていないヘッダが結果を変える」欄。

## 実行

```bash
bash scenarios/002-expect/run.sh
```
