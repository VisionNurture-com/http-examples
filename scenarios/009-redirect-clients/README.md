# 009-redirect-clients — 言語ごとの HTTP クライアントは Authorization を落とすか

## 何を測るか

`009-redirect-origin`（curl）と `009-redirect-browser`（ブラウザ）と同じ 7 ケースを、**各言語のランタイム**で測ります。

仕様（WHATWG Fetch）はブラウザの規定で、コマンドラインツールや各言語の HTTP クライアントを縛りません。実際にどう振る舞うのかは**測らないと言えません**。

## 記事のどこに出るか

決定表「リダイレクトを越えると `Authorization` はどうなるか」の**クライアント別**の行。

## 判定

終端 `/009/whoami` が自分で報告した到着内容だけを読みます。クライアントが自分で報告した内容は使いません。

## 測定の条件について

`B4`（http → https）はローカルの証明書を使います。ブラウザと `curl` は OS の信頼ストアを見るので通りますが、python / java / node / bun はそれぞれ別の信頼ストアを持つため、何もしないと **TLS の検証で失敗**します。それは「`Authorization` が落ちた」ではないので、**信頼だけを各ランタイムへ渡して**測定から取り除いています。信頼ストアの設定は、リダイレクト時のヘッダの扱いを変えません。

## 測れない範囲

**ここで測ったのは各ランタイムの既定（と、リダイレクトを追わせるのに最低限必要な設定）だけ**です。ライブラリを差し替えたり、リダイレクトを自分で実装したりした場合は別の結果になります。
