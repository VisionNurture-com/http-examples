# 003-query-method — 新しいメソッドにも「宣言と実装」のずれはあるか

## 何を測るか

[RFC 10008](https://www.rfc-editor.org/rfc/rfc10008.html)（2026-06・Proposed Standard）が定めた QUERY メソッドは、
IANA の HTTP Method Registry に **Safe = yes / Idempotent = yes** で登録されている。

記事 003 の主題は「仕様が決めているのは名前の意味であって、あなたのハンドラの動きではない」ことなので、
**PUT で測ったのと同じ 3 回送りを QUERY にも当てる**。読むだけの実装と、読むだけのつもりで数を進める実装の 2 系統を置く。

あわせて、**メソッド名を小文字で書いたときに何が起きるか**も記録する。
Fetch 標準が正規化するのは `DELETE` / `GET` / `HEAD` / `OPTIONS` / `POST` / `PUT` の 6 語だけで、
`QUERY` はそこに含まれない。GET を対照に置いて、正規化される語とされない語の差を出す。

## 記事のどこに出るか

- 仕様の分類表（安全・冪等）に QUERY の行が増える
- 「送ったつもりのメソッドが届かない場所」に、**メソッド名の大文字小文字**が加わる

## 実行モード

**M1**（curl のみ・ブラウザ不要）。CI で回る。

## 測り方

- 系統ごとに `POST /003/__reset` で初期化する。状態はアプリのプロセス内に残るため
- 判定に使うのは `GET /003/state` の `quota`。応答のコードや本文では判定しない
- Express に `app.query()` は無いため `app.all` で受け、QUERY 以外は 405 で弾いている
