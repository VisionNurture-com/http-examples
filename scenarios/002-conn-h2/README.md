# 002-conn-h2 — h1 用のヘッダを h2 で送る

## 何を測るか

RFC 9113 §8.2.2 は、`Connection` などの**接続固有ヘッダ**を含む HTTP/2 リクエストを malformed と定めています。h1 のリクエストをそのままコピーして h2 の口へ投げたとき、**誰がそれを止めるのか**を測ります。

対象は `Connection` / `Keep-Alive` / `Upgrade` / `Transfer-Encoding` の 4 本です。

## 判定でつまずく点

`curl -v` の `> Name: value` 行は、curl の**論理的な要求表示**であってワイヤに出たバイトではありません。ここを読むと「サーバまで届いた」という誤った結論になります。

実際に HEADERS フレームへ入ったものは、`* [HTTP/2] [1] [name: value]` の行にだけ出ます。**そちらを読みます。**

## 記事のどこに出るか

決定表の「コピー元とコピー先でプロトコルが違うと、そもそも同じ要求にならない」欄。

## 実行

```bash
bash scenarios/002-conn-h2/run.sh
```

TLS の口（8443）へ h2 で接続します。証明書は `tools/gen-certs.sh` で用意します。
