# 005-fetch-timeout-browser — ブラウザの fetch は何秒待つか

## 何を測るか

`005-fetch-timeout` と**同じ足場**（`GET /005/never-responds`）へ、3 つのブラウザエンジンから `AbortController` なしの `fetch` を投げます。同じ `fetch` という名前の API が、サーバ側とブラウザ側で同じ既定を持つのかを確かめます。

## 記事のどこに出るか

決定表の前段。**「どこで動かすかで既定が違う」ことを示す実効値。**

## 判定

上限で当方が打ち切ったかどうかは、`abort()` の理由に載せた文字列ではなく**フラグ**で判定します。

🔴 **2026-08-25 の初回測定で、ここを取り違えました。**`abort(new DOMException("__CAP__"))` の文字列で判定していたところ、WebKit はこれを `Fetch is aborted` に差し替えて返すため、**WebKit だけ「エンジンが切った」と誤判定**しました。経過が上限ちょうどの 330.0 秒だったことで気づき、フラグ方式へ直して測り直しています。**エンジンが返す文言を判定に使ってはいけません。**

## 🔴 同梱ブラウザで測っています

Playwright が同梱するブラウザで測った値です。**実際に配布されているブラウザでは測っていません。**同梱版は実ブラウザの代理になりません。

## 測れない範囲

- **実ブラウザは未測定**（上記）
- **接続タイムアウト**は測っていません（接続は成立させています）
- **上限は 330 秒**です。それより長い既定値があれば「切れなかった」としか言えません
- タブが背面にある場合・省電力状態・ネットワークが切断された場合は測っていません
