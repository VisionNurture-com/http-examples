# 006-immutable-boundary — immutable が効く条件を絞り込む

## 何を測るか

通常ナビゲーションとリロードでは 3 エンジンとも差が出ませんでした。そこで「まだ効く経路が残っていないか」を潰しにいきます。

| 経路 | 何を見るか |
|---|---|
| `stale` | 期限切れ後。immutable は fresh のあいだだけ意味を持つ（RFC 8246）ので、境界を確かめる |
| `restart` | プロファイルを閉じて開き直したあと。ディスクキャッシュが残るか |
| `fetch-nocache` | スクリプトから `fetch(url, { cache: "no-cache" })` で明示的に再検証を要求したとき |
| `fetch-reload` | 同じく `{ cache: "reload" }` |

## 記事のどこに出るか

実効値の表「immutable は今も効くのか」の条件欄。

## 判定

006-immutable と同じ。サーバ側の到着記録と status。

## 対照（測定の事前条件）

測定の前に 3 つの対照を取り、1 つでも崩れたら値を書き出さずに中止します。

| 対照 | 変種 | 崩れたときに疑うこと |
|---|---|---|
| 陰性 | `max-age=600` の 2 回目が 0 件 | そもそもキャッシュが働いていない |
| 陽性 | `no-store` の 2 回目が必ず到着 | 観測チャネル（nginx のログ）が死んでいる |
| 条件付き | `no-cache` の 2 回目が 304 | 「訊きに来たこと」を観測できていない |

3 つ目がないと、「到着 0 件」を「条件付きリクエストすら出さなかった」と読むことができません。沈黙と測定値の区別がつかないためです。
